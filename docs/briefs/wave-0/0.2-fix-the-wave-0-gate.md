# Brief 0.2: fix what the wave 0 gate review found

Before you write anything, read these five files in this order: `CLAUDE.md` for the rules and the commands, `COEUS.md` for the plain-words explanation of the state design and the check table that ties each claim to a brief and a test, `ARCHITECTURE.md` for how the code is put together and what earlier waves built, `REPO_MAP.md` for where everything lives, and `docs/NERDGENIE_PLAN.md` for the design you are implementing, especially the section this brief names. Then read this brief and the reference files it points at. You own exactly one package. Write the tests first.

## What this brief is

Wave 0 was merged into `main` and then reviewed by a reader with fresh eyes. The review found twenty-five problems, listed below in the reviewer's own words, and nine of them disable a safeguard every later wave leans on. You fix all twenty-five. For this brief you own `internal/testkit`, `internal/lint`, `scripts/`, the `Makefile`, `.github/workflows/check.yml`, `test/fixtures/forty-step/`, `test/functional/sample_test.go`, and, for finding 18 only, `cmd/nerdgenie/main.go`, which is otherwise the orchestrator's file. You do not touch `internal/contract` (report if a finding needs it), and you do not touch any other package.

**Order matters.** Five wave 1 and wave 2 workers are building against these fakes right now. Do findings 4, 5, and 6 first (the fake provider server), commit them as their own test-then-code pair, and keep going; the orchestrator will bring that commit onto `main` early so the provider worker can rebase. Then findings 1, 2, 3, 7, 8, and 9. Then the rest in order.

**The method for every finding.** First commit a failing test that demonstrates the problem exactly as the reviewer proved it (the mutation or the probe described), then commit the fix that makes it pass. Where the reviewer says a test passes by accident, make it a test that fails under the named mutation. Keep every function under sixty lines and every file under five hundred; split files where a fix would push one over.

## The findings, in the reviewer's words

1. **The coverage gate lets any package with no test file through.** `scripts/coverage.sh:68` filters `go test` output with `grep -E '^(ok|FAIL|---|\?)'`, but under `-cover` Go prints an untested package as a tab-leading `\tgithub.com/…/pkg\t\tcoverage: 0.0% of statements` line, which matches no prefix and is dropped before the loop. Proven on a copy: a new `internal/untested` with one exported function and no `_test.go` produced no row and did not set `failed`. It also makes the `no test files` branch at `coverage.sh:43-47` dead code. Fix: drive the loop from `go list ./internal/... ./scripts/...` so a package missing from the output is a failure, and match on the `coverage:` substring rather than a line prefix.

2. **The forty-step fixture never makes the model write to the record.** `FortyStepRound.TaskUpdate` (`internal/testkit/fortystep.go:36`) carries the why/done/stop list (round 1), the ten-step plan (round 4), the failure (round 6) and the decision (round 12), and no non-test file ever reads it: `stepFor` (`fortystep.go:148-166`) emits only `round.ToolName`, so the script never produces a `task` tool call. `RecordAtTheEnd` (`internal/testkit/fortystepchecks.go:18-42`) builds `Work{Results: lines}` only, no plan, no decisions, no failures, no situation lines. A harness that never writes the plan or the decision passes all three assertions. Fix: emit the `task` update as a second tool call in the same reply (renumbering results accordingly), and fill `RecordAtTheEnd`'s plan, decisions and failures from the fixture data.

3. **The stop at round thirty and the resume are data the code never uses.** `StopRound` and `UserReplyAfterStop` (`fortystep.go:87,89`) are read by no production code; `Script()` returns forty steps back to back with no pause at thirty and no step requiring the user's reply. `TestTheStopConditionFiresAtRoundThirtyAndTheUserLetsItResume` (`fortystep_test.go:73-85`) only reads the two JSON fields back out. A harness that ignores the stop list and runs all forty rounds passes. Fix: in `stepFor`, give rounds after `StopRound` `Expect: []string{task.UserReplyAfterStop}`, mirroring the correction, and make the test prove that a script driven without the reply fails at round thirty-one.

4. **The fake provider server ignores `Step.Expect`.** `nextStep` (`internal/testkit/providerserver.go:189-201`) pops the step without checking expectations; `Expect` appears nowhere in `providerserver.go` or `providerstream.go`, while `FakeModel.nextStep` (`model.go:135-158`) does check. Fix: decode the request body in `handle` (both wire shapes: the Anthropic `system` blocks and `messages`, and the OpenAI `messages`) and run the same `strings.Contains` check the fake model runs, failing the call with the same message and a 400 the client can read.

5. **Both wire protocols drift from what wave 1's brief requires.** `docs/briefs/wave-1/1.4-model-providers.md:15` requires accumulating `delta.tool_calls[]` by index because the id and name arrive on the first delta and the arguments in pieces, and reading usage from a final chunk whose `choices` is empty; but `providerstream.go:114-125` sends the whole `function.arguments` string in one chunk and attaches `usage` to the chunk that carries `finish_reason` with a non-empty `choices`. The Anthropic side splits `input_json_delta` correctly but emits no `ping` and no `error` event, and hardcodes `cache_creation_input_tokens: 0` (`providerstream.go:42`) with the field absent from `message_delta`. Fix each to match the brief's stated shapes: OpenAI tool-call arguments in at least two pieces per call, usage in a separate final chunk with empty `choices`, then `data: [DONE]`; Anthropic `ping` events between blocks, an `error` event when the step says to misbehave mid-stream, and cache-creation tokens from the step's usage.

6. **Two of the four finish reasons can never come off the wire.** `finishReasonFor` (`providerserver.go:211-223`) returns only `tool_use`/`end_turn` and `tool_calls`/`stop`, so `contract.FinishLength` and `contract.FinishStopped` are unreachable, yet the brief requires mapping `max_tokens` to length, `refusal` to stopped, `length` to length and `content_filter` to stopped. Fix: derive the wire word from the step's finish reason rather than from whether tool calls are present, and add a fixture step for each.

7. **The repo-map generator's `git` child inherits `GIT_*`.** `scripts/repomap/generate.go:94` runs `git -C root ls-files -z` with the inherited environment, and `GIT_DIR` outranks `-C`: with `GIT_DIR` set, a fresh one-file fixture returned this repository's tracked files and `TestGenerateProducesTheSameMapEveryTime` still passed. `generate_test.go:22-31` strips `GIT_*` only from the fixture setup commands, not from the code under test. Fix: set `command.Env` in `trackedFiles` to `os.Environ()` minus every `GIT_`-prefixed entry, and test it with `GIT_DIR` pointed at the real repository.

8. **`CheckSandbox` asserts nothing against a working sandbox.** `internal/testkit/checks_run.go:15-18` returns `nil` at once whenever `Available() == nil`; `sandbox_test.go:54` calls it on a fresh, available fake, and replacing the whole body of `FakeSandbox.Run` with a constant success leaves that test passing. Fix: assert something about the available case (an unscripted command errors, a recorded command comes back) and have the test also flip the sandbox unavailable.

9. **Lint rule 7 is case-sensitive and misses seven of the nine reference projects.** `internal/lint/comments.go:13-16` hardcodes `"OpenClaw", "Hermes", "OpenCode", "ZeroClaw", "HomeRecon", "browser-use", "Moltis", "Codex", "prime-agent", "Prime Agent"` and matches case-sensitively at `comments.go:44`. Headers naming `openclaw`, `opencode`, `zeroclaw`, `homerecon`, `codex`, `moltis` or `hermes-agent` with no reference path report nothing, and those lowercase folder names are exactly what `CLAUDE.md` teaches a worker to write. Fix: fold case and use the folder names, with a test row per project.

10. **`FakeChannel.Receive` never closes, and `Push` hangs when full.** `internal/contract/channel.go:72-74` promises the stream closes when the context is cancelled or the channel shuts down, but `internal/testkit/channel.go:124-126` returns one shared channel that stays open after cancellation and hands the same channel to every caller. `channel.go:59` and `signalcli.go:104` both use a blocking send on a 64-slot buffer, so overflowing the queue hangs the test rather than failing it, while `internal/testkit/doc.go` claims a scripted queue runs out with a clear error rather than blocking. Fix: a per-call channel closed on `ctx.Done()`, and a non-blocking send that reports the overflow.

11. **`FakePermission.Remember` records answers nothing ever reads.** `internal/testkit/permission.go:82-89` files `once`, `always` and `reject` into one undifferentiated slice, and `Decide` (`permission.go:67-79`) consults only `byTool` and `byDefault`. Rewriting `Remember` so a remembered reject is filed as always with its reason discarded leaves the whole suite green. Fix: make `always` allow the same request for the session, `reject` deny it with its reason, `once` change nothing, and prove each in the fake's test and in `CheckPermission`.

12. **The browser fake leaks a credential through `NewElements`, and its two forms disagree.** `scrubCredentials` (`internal/testkit/browser.go:286-301`) hides the values in `Seen`, `URL`, `Snapshot.Title` and `Snapshot.Elements[].Name` but not `Diff.NewElements[].Name`, and both `browser_test.go:170-173` and `checks_screen.go:64-71` build their haystack from the same four places. Separately, `answer` (`browserserver.go:114-117`) discards `result` whenever `err != nil`, so an `act` that aborts loses every diff collected before the abort, though `PROTOCOL.md` promises one diff per step that ran and the in-process fake returns them. Fix both; search the whole JSON of the response in the check.

13. **The browser protocol server has no deadlines, a silent 64 KB line cap, and collapses every unrecognised error to -32602.** `serve` (`browserserver.go:84-95`) blocks on `lines.Scan()` with no read deadline and never checks `lines.Err()`; a request line over the scanner's default cap ends the connection with no error answer; `accept` loops with no bound; `run` uses `context.Background()`. `codeFor`'s default maps everything unknown to "the parameters were wrong", so the fake's own "no page is open" never surfaces as -32002, and -32600/-32003 are unreachable. `Open` returns a `Snapshot`, which has no wall field, so opening the login or captcha fixture directly reports no wall. Fix: deadlines, an explicit cap answered with -32700, the error table mapped in full, and report the wall from `open` the way `PROTOCOL.md` says a method that runs into a wall does (if that needs a change to the protocol document or to `contract`, stop and report it).

14. **The signal-cli fake cannot test the two things its levers exist for.** `DropStream` (`signalcli.go:124-132`) closes a one-shot channel with no reopen, so every later connection returns immediately and the reconnect-after-drop path can never be exercised; `StallStream` (`signalcli.go:135-140`) stalls once before the first byte and never clears, so it models a connect stall rather than a stream going quiet mid-flight. `signalcli.go:225` also emits `{"filename": <base>, "id": <full local path>}`, conflating signal-cli's opaque attachment id with a filesystem path. Fix: a drop that closes the current stream and lets the next connection succeed, a stall that goes quiet after some bytes on the current stream only, and an opaque id served through the daemon's attachment endpoint the way signal-cli does.

15. **The fake sandbox picks a scripted prefix out of map order and ignores the context, the timeout and the roots.** `sandbox.go:69-73` ranges over a map, so with both `"git"` and `"git status"` scripted the short prefix wins most runs. `Run` (`sandbox.go:59`) discards the context and never reads `command.Timeout`, and accepts a working directory inside the vault plus a secret in the environment with no error, though `contract/sandbox.go` forbids both. Fix: longest-prefix match over sorted keys, an expired context reported as timed out, and a roots list enforced.

16. **The redactor corrupts already-redacted text.** `internal/testkit/secrets.go:72-77` chains `strings.ReplaceAll` over the live text, so a short secret matches inside a marker a previous pass wrote: with `"hunter2hunter2"` and `"act"` held, `Redact("logging in with hunter2hunter2 now")` returns `"logging in with [red[redacted]ed] now"`. Its longest-first ordering is asserted nowhere, and `Redact` has no fuzz target. Fix: collect match spans over the original text and splice in one pass; add the fuzz target.

17. **`FakeSkill.Save` throws away the body and the triggers.** `internal/testkit/skill.go:113-116` builds the replacement entry with only `summary` and `files`, so saving over an existing skill makes `Load` return `""` and `Match` return `false`. `firstLineOf` (`skill.go:137`) returns the markdown heading, so a `SKILL.md` of `# post-to-x\nPosts one message to X.` yields the folder name as the description. Fix both with tests that fail under the current code.

18. **`cmd/nerdgenie/main.go` has no 75/78 exit-code mapping, and a comment claims it does.** The comment at `main.go:39-42` states the codes come from `internal/contract`, but `run` returns only `ExitOK` and `ExitUsage`. `help` is special-cased rather than being a table row, so `main_test.go:74-85`'s duplicate-detection branch can never fire; `-h`/`--help` and the leading-`/` strip in `Lookup` both survive deletion with the package green. Fix: a subcommand's run function returns an exit code and `main` exits with it, with a test per code; `help` becomes a table row; a test per deletion.

19. **The job fake's state machine does not do what the contract says.** `RunNow` (`internal/testkit/job.go`) only sets the state and never clears the next task's due date, so `NextTask` still refuses it; `setState` stamps `LastRun` on pause and switch-off, though it means when a task last finished; `TestTheFakeJobStorePausesRunsAndSwitchesOff` only reads state back out of `List`, so deleting the `state != JobRunning` guard in `NextTask` leaves the package green. The ten-failure rule is unreachable through `NextTask` because `applyFailureCount` pauses at three first, and a tick behind a future-dated task is lost because `tickSchedule` advances `NextRun` while `NextTask` breaks at the first not-yet-due task. Fix: `RunNow` clears the due date of the next task; `LastRun` moves only in `FinishTask`; a scheduled job is not paused at three but switched off at ten, and a plain job is paused at three; a tick's task is inserted before the first not-yet-due task so it runs when due; and tests that fail under each of the old behaviors.

20. **Unbounded outside calls in three places.** `scripts/repomap/generate.go:94-96` runs `git ls-files` with no `CommandContext`, no timeout and an unbounded `Output()` buffer, and `generate.go:74-79` discards git's error and silently falls back to a filesystem walk that lists untracked files. `providerserver.go:124` does `io.ReadAll(request.Body)` with no `MaxBytesReader` and drops the error. `internal/lint/lint.go:105` reads every `.go` file with no size cap. Fix all three with a timeout, a cap, and an error that says what happened.

21. **`make check`'s gofmt step scans other workers' worktrees and swallows gofmt's exit status.** `Makefile:33` uses `find .`, which descends into `.claude/worktrees/`, while `go vet`, `staticcheck` and the style checker use `./...`. The `$$(find …)` substitution is unquoted, so a path with a space makes gofmt exit 2 while the gate reports success. Fix: `gofmt -l` over `git ls-files '*.go'` with quoting, and check gofmt's status as well as its output.

22. **Missing fuzz targets the definition of done names.** There is no `testing.F` anywhere in `internal/testkit` or `scripts/repomap`, though `BrowserProtocolServer.answer` parses JSON-RPC lines off a socket, `trackedFiles`/`excludedPath` parse NUL-separated path bytes, and `FakeSecrets.Redact` parses arbitrary text; the fake provider server's request decoder must exist (finding 4) and be fuzzed. `scripts/fuzz.sh:23` pipes `go test -list` through `2>/dev/null … || true`, so a package whose test binary does not build is silently skipped, and it omits `-tags integration`. Fix all.

23. **Several lint rules are weaker than the brief and their data lists are untested.** Rule 5 is defeated by an import alias or dot import (`internal/lint/errormessage.go:44-57` requires the callee's package to be literally `errors` or `fmt`) and counts format verbs as words. Rule 1 reads only `.Doc` groups, never `ast.Field.Comment`, so a trailing comment on an exported field is unchecked. Rule 6's `t,b,f,r,w` exemption applies in every file, though the brief limits it to tests and handlers. Neither length rule has a boundary test (the fixtures are 67 body lines and 505 file lines), and only two of nine banned abbreviations and three of ten project names are covered. `TestSourceThatWillNotParseIsLeftToTheCompiler` asserts zero violations on input that yields zero either way, and a file that will not parse passes `scripts/stylecheck` with exit 0. Fix: resolve the import by path through the file's imports, count words with verbs stripped, read field comments, limit the exemption to tests and handlers, boundary tests at exactly sixty and sixty-one and five hundred and five hundred and one, a row per abbreviation and per project, and a parse failure that is reported as a violation naming the file.

24. **Weaker tests, each with the mutation that should fail it.** `TestTheBrowserProtocolServerAnswersHealthAndTheEightOtherMethods` asserts only that `answer["error"]` is absent; check `diffs`, `tabs`, `pngBase64` and `marks` against `PROTOCOL.md`'s examples. `TestTheTemporaryHomeIsRealOnDiskAndHoldsWhatTheFakesWrite` writes and reads the bytes itself with no production code between. `TestTheTemporaryHomeIsSomewhereTemporary` passes with `t.TempDir()` replaced by a fixed shared folder. `TestRunWithNoRootUsesTheCurrentFolder` passes with `root := "."` changed to `".."`. Deleting `slices.Sort(paths)` and removing `.git` from `excludedFolders` each fail nothing. `TestTheFakeSearchServerAlsoServesADuckDuckGoResultsPage` passes with every `href` and snippet stripped. `test/functional/sample_test.go`'s one-second bound is measured after the fact, and `FakeModel.Send` discards its context, so a hung model call would hang the template every later functional test copies. Fix each so the named mutation fails it, and make the fake model honor its context.

25. **Smaller, but they will bite.** The DuckDuckGo fixture serves direct `href`s where the real endpoint wraps every result in a `//duckduckgo.com/l/?uddg=…` redirect; the search server has no timeouts, no misbehave switch, no request record, and returns the same two results for any query including none. `FakeMemory.Hint` returns superseded facts. `FakeDesktop` accepts mark 0 and records a drag before refusing it. Fix each.
