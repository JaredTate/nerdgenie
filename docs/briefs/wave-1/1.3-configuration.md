# Brief 1.3: configuration and the home folder

Before you write anything, read these five files in this order: `CLAUDE.md` for the rules and the commands, `NERDGENIE.md` for the plain-words explanation of the state design and the check table that ties each claim to a brief and a test, `ARCHITECTURE.md` for how the code is put together and what earlier waves built, `REPO_MAP.md` for where everything lives, and `docs/NERDGENIE_PLAN.md` for the design you are implementing, especially the section this brief names. Then read this brief and the reference files it points at. You own exactly one package. Write the tests first.

## The package

`internal/config`. One sentence: the configuration file and the home folder layout, loaded once and checked. `ARCHITECTURE.md`, "Data on disk"; design section 6 ("Model providers": the model name and the fallback chain are set in the configuration) and section 11 (the sandbox roots, the vault, the backups). The plan text is `docs/WORK_PLAN.md`, Part 3, Brief 1.3. The configuration struct with every field and its default is already in `internal/contract` from wave 0; read it first, and do not redefine it. If a field the plan names is missing from `contract`, stop and report.

## What to build

- **Load.** Read `~/.nerdgenie/config.toml` once into the `contract` configuration struct, starting from the defaults `contract` provides, so an empty file is a valid configuration. Use `github.com/BurntSushi/toml`, which is pre-approved in `docs/DEPENDENCIES.md`; add the `require` line and run `go mod tidy`. Decode strictly: an unknown key is an error that names the key and the line, because a misspelled option must never be silently ignored.
- **Check.** After decoding, validate every field, and every error names the key and, when the parser gives it, the line, and says what to do. The rules that must hold: every model alias has a provider kind that is one of the two, a base address that parses as a URL, a model name, and a context length above zero; the default model and every entry in the fallback chain name an alias that exists; the local model alias defaults to the llama-server daemon in `CLAUDE.md` (`http://127.0.0.1:19091/v1`, model name `local-coder`, context 262144, no key); a key reference, when present, has the `secret://` form; the sandbox roots are absolute paths and never include `~/.nerdgenie` itself, the vault file, the browser profile, or `~/.ssh`, or any parent of those; every cap is above zero and the budget caps default to the design's numbers (one hundred rounds, one hour, seven minutes per tool, fifteen minutes per turn, one hundred queued messages); the handoff timeout is positive; the Signal account, when set, looks like a phone number in international form; the backup path and the search server address, when set, parse.
- **The home folder.** Functions for the layout in `ARCHITECTURE.md`: the root (from `$NERDGENIE_HOME` if set, else `~/.nerdgenie`), each path under it, and the file modes (the root, the vault key, and the browser profile are private to the user). `contract` may already hold the path helpers; if so, this package uses them and adds only what is needed here.
- **Doctor.** A function that takes the home root and reports what exists and what does not, what has the wrong mode, whether the configuration loads, and whether each outside program Nerd Genie needs is on the PATH (signal-cli, bwrap, rg, google-chrome or chromium, node), plus whether the local model daemon answers its health check at the configured address. It never changes anything. It returns a structured report with one line per check and an overall verdict, and a printer turns the report into plain text a person can read. `nerdgenie init` in wave 3 calls the doctor and prints it; `nerdgenie doctor` in wave 3 is a subcommand file that does the same.

## What not to build

No environment-variable overrides beyond `$NERDGENIE_HOME`. No hot reload. No writing of the configuration file; `init` in wave 3 writes it through a template it owns. No option the plan does not name.

## Tests, in the order you write them

1. Defaults from an empty file equal the `contract` defaults, field by field.
2. A table test that sets every field, one at a time, to a value of the wrong type or an impossible value, and asserts the error names the key and the line.
3. An unknown key is an error naming it.
4. Each sandbox root rule: a root inside `~/.nerdgenie`, a root that is `~/.ssh`, a root that is a parent of the home, each refused with a message that says why.
5. The doctor on an empty home from `testkit`, and on a full one the test builds, with a fake PATH that has and lacks each program, and with the daemon address pointed at a `testkit` server that answers and at a closed port.
6. The integration test loads a real file from a temporary home and runs the doctor against it.
7. A fuzz test on the loader: any bytes produce a configuration or an error, never a panic.

## Definition of done

Everything in "Definition of done, for every package" in `docs/WORK_PLAN.md` Part 1. `make check` clean on your branch. `ARCHITECTURE.md` updated for this package. `REPO_MAP.md` regenerated. You do not touch any other package.
