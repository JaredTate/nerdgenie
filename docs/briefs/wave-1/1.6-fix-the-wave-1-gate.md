## internal/permission (its gate is not passed until these are closed)

1. **The reducer silently truncates, and the ask-me-first list never sees the tail.** `internal/permission/reduce.go:367` cuts the readable form at 200 runes, `internal/permission/shellwords.go:37` stops reading at 64 segments or 8192 bytes, and in all three cases the dropped text is where the dangerous command sits. Demonstrated: `strings.Repeat("echo hello; ", 40) + "rm -rf /home/jared/coeus"`, 504 bytes, 41 segments, inside every documented bound, reduces to 200 runes of `echo | echo | …` and `Rulebook.Match` returns `covered=false`, so the call runs unasked. Fix: fail closed. When `oneLine` truncates, or when `commandWords` hits either cap, return a form the ask rules match, or have `Decide` rule ask outright, because a bound that hides the end of a command is a bound that disables the rule.

2. **`sh -c "rm -rf ~"` reduces to `sh -c` and matches nothing.** `internal/permission/reduce.go:51` gives an unnamed program `defaultShape{words:1, keepFlags:true}`, so at `reduce.go:163-174` the quoted script, one word after the splitter, is discarded; `bash -lc 'rm -rf ~'` reduces to `bash -lc`. This is the form a model writes constantly and the form a prompt injection inside a tool result would use, and neither `deletePatternsByTool` (`askmefirst.go:26`) nor the near-miss table (`askmefirst_test.go:57`) contains a single nested-shell case. Fix: when the program's base name is `sh`, `bash`, `zsh`, or `dash` and a `-c` follows, reduce the script that follows as a command of its own, recursively, with a depth cap.

3. **`/usr/bin/sudo -u root …` slips past the sudo entry.** `internal/permission/reduce.go:151` only prefixes `sudo ` when `words[0]` is exactly `"sudo"`, and the two patterns at `internal/permission/askmefirst.go:44-47` are `sudo*` and `* sudo*`, so the reduced form `/usr/bin/sudo -u` matches neither. Fix: compare `filepath.Base(words[0])` against `sudoProgram`, and do the same wherever a program name is matched.

4. **A subshell splits the program away from its arguments.** `commandSeparators` at `internal/permission/shellwords.go:29` treats `(`, `)` and the backtick as command separators, so `$(printf rm) -rf /home/jared/coeus` reduces to `$ | printf | -rf /home/jared/coeus` and matches nothing. Fix: a substitution or a backtick anywhere in a shell command forces ask.

5. **The fuzz test cannot catch any of the four above.** `internal/permission/fuzz_test.go:12` and `:29` seed `"rm -rf $(echo /tmp)"` but only call `checkReadableForm`, which asserts the output is one line inside the cap, never that a command which really deletes still matches a rule. The one change that should make a test fail but would not: wrap any `bulkDeleteCalls` entry in `sh -c '…'` and every test in the package stays green. Fix: add a property to the fuzz target that any command whose words contain a deleting form is still matched by the shipped rulebook, seeded with the four cases above wrapped in `sh -c`, a pipe, a subshell, and a long prefix.

## internal/sandbox (its gate is not passed until these are closed)

6. **A sandbox root that is a symbolic link puts `~/.ssh` and the vault inside the fence.** `internal/sandbox/roots.go:53-57` compared cleaned strings and never resolved links; confirmed with the real bwrap that `--bind <link> <link>` binds the target, so a fixture `id_rsa` under a linked directory was readable and the Landlock rule granted full access to the same path. The contract's `CheckSandboxRoot` now follows links on both sides; fix the package to use the resolved path for the bwrap bind and the Landlock rule, and add integration tests with a linked root to the home and to `~/.ssh`.

7. **`$COEUS_HOME` moves the agent home but not the exclusion list.** The excluded paths were built from `~/.coeus` while `$COEUS_HOME` can put the real home, the vault, and the browser profile anywhere; with the home at `~/work/agenthome`, `checkRoots(["~/work"])` was accepted and the vault would be bound read-write. The contract's `ExcludedFromSandbox(userHome, agentHome)` and `sandbox.Settings.AgentHome` now exist; test that a moved home is excluded and document that `serve.go` passes the real `contract.Home` root.

8. **The fence sets a PATH the helper never uses.** `internal/sandbox/entry.go:94` calls `syscall.Exec(request.program, …)`, which does no PATH search, while `internal/sandbox/arguments.go:29` sets `PATH=/usr/local/bin:/usr/bin:/bin` inside the fence; every test passes an absolute path, and brief 2.5's shell tool passing `sh` will get an error that blames the wrong thing. Fix: look the program up on the fence's PATH inside the helper after Landlock, and say "a full path or a program on the fence's PATH" in the error.

9. **`TestTheNamespaceProbeIsRunOnceAndItsAnswerRemembered` does not test what it is named.** `internal/sandbox/available_test.go:191` asserts only that `fence.probed` is set and that two answers are equal; deleting the `if !fence.probed` guard in `available.go:55` leaves the test green. Fix: count the probes through an injectable prober.

10. **`TestAvailableOnThisMachineReadsTheRealPathAndTheRealKernel` (`available_test.go:164`) asserts nothing on the success path.** Give it a real assertion or fold it into the integration suite where `Available()` must return nil.

11. **Two pieces built ahead of need.** The user-namespace probe and `Settings.HelperProgram` are defensible; record in `doc.go` and `ARCHITECTURE.md` that they are deliberate additions and why.

## internal/provider (its gate is not passed until these are closed)

12. **A retry replays deltas the caller has already seen.** `internal/provider/retry.go:65` and `internal/provider/chain.go:161` hand the same `onDelta` to every attempt, and both stream readers call it as text arrives, before any failure. A model that streams `"Hello "` then rate-limits and on the second attempt streams `"Hello world"` gives the caller `"Hello Hello world"` while `reply.Text` is `"Hello world"`. Fix: gate the deltas per attempt so the caller sees only the successful attempt's text, and add that assertion to both `retry_test.go` and `chain_test.go`.

13. **The system-prompt cap is four times the kernel's per-argument limit.** `internal/provider/cli.go:24` sets `maxSystemPromptBytes = 512 << 10` and `cliarguments.go:266` puts that value in argv; `MAX_ARG_STRLEN` on this machine is 128 KiB, so a prompt between the two fails with "argument list too long" instead of a clear refusal. **14. The claude path publishes the whole system prompt in the process table** through `--system-prompt <text>`, while the codex path writes a file. Fix both at once: pass the system prompt to `claude` through `--system-prompt-file` under the same scratch folder, delete it after the call, and correct the doc comment at `cliarguments.go:243` that claims nothing of the conversation is on the command line.

15. **`props.go` is code before test.** `props.go` shipped in the code commit before its tests, and `parts_test.go` is a coverage-filling test written after its code. Do not rewrite history; say so in `ARCHITECTURE.md`'s provider paragraph in one sentence.

16. **A zero output cap goes straight onto the wire.** `internal/provider/anthropic.go:79` sets `MaxTokens: request.MaxOutputTokens` with no default and no check, and a 400 comes back that is neither sentinel. The contract now has `Caps.OutputTokensPerCall` (default 8192); take it when the request's cap is zero, and refuse a request whose cap is still zero by name.
