## What to build

- **Availability.** `Available()` returns nil when `bwrap` is on the PATH and the kernel reports Landlock (the `landlock` word in `/sys/kernel/security/lsm`), and otherwise an error that says which is missing and what to install. The shell tool of brief 2.5 calls this and turns itself off.
- **The fence.** `Run` builds a `bwrap` command line: a new user, pid, ipc, and uts namespace (`--unshare-user --unshare-pid --unshare-ipc --unshare-uts`, never `--unshare-net`, because the network is allowed), `--die-with-parent`, `--new-session`, a fresh `/tmp`, `/proc` and `/dev` mounted fresh, the system folders (`/usr`, `/bin`, `/lib`, `/lib64`, `/etc`) bound read-only, each sandbox root from the configuration bound read-write at the same path, and nothing else. The home folder is not bound. `~/.nerdgenie`, the vault, the browser profile, and `~/.ssh` are never bound, and a configured root that contains any of them is refused at construction with an error naming it (the configuration package refuses it too; you refuse it again, because this package is the last line). The working directory is one of the roots. The environment is a short allow list (`PATH`, `HOME` set to a scratch folder under the first root, `LANG`, `TERM`) plus what the caller passes.
- **Landlock and seccomp inside the fence.** bwrap does not apply Landlock, so the command runs through an entry helper: `bwrap ... -- <the nerdgenie binary> sandbox-entry <options> -- <program> <args>`. The entry helper is a function in this package that the orchestrator wires as a hidden subcommand in `cmd/nerdgenie/main.go`; you write it in your own file `cmd/nerdgenie/sandbox_entry.go` as a subcommand value and say so in your report. The helper locks its OS thread, builds a Landlock ruleset with the raw syscalls (`landlock_create_ruleset`, `landlock_add_rule`, `landlock_restrict_self`, numbers 444, 445, 446 on both `amd64` and `arm64`, through `syscall.Syscall` with the structs laid out by hand; use the ABI version the kernel reports and fall back to version one), allowing read and execute on the read-only folders and full access on the roots, sets `PR_SET_NO_NEW_PRIVS`, installs a seccomp filter that denies a short list of syscalls no tool needs (`mount`, `umount2`, `pivot_root`, `ptrace`, `kexec_load`, `init_module`, `finit_module`, `delete_module`, `reboot`, `swapon`, `swapoff`, `setns`, `unshare` for new user namespaces, `bpf`, `perf_event_open`, `keyctl`) by returning `EPERM`, with the BPF program encoded by hand as `sock_filter` words, and then calls `syscall.Exec` on the program. The restriction carries across the exec. Everything the helper does is logged to standard error in one line so a failure can be read.
- **Running.** The command runs in its own process group. Standard input is passed from the caller, standard output and standard error are captured with a cap each (the tool output cap from `contract`), and anything past the cap is dropped with a note. The timeout comes from the caller's context; on timeout or cancel the whole process group is killed, first with `SIGTERM`, then two seconds later with `SIGKILL`. The result has the exit code, whether it timed out, and both streams.
- **Bounds.** The argument list is capped in length; the environment is capped; the number of roots is capped.

## Tests, in the order you write them

Unit tests (`*_test.go`, nothing installed) cover everything that does not execute: the bwrap argument builder on a fixture configuration (golden), the root refusal for each forbidden path and for a parent of the home, the environment allow list, the Landlock rule builder's struct encoding against known byte layouts, the seccomp program's encoding against a golden byte sequence, and a fuzz test on the argument builder (any roots and any command, no panic, and never a `--bind` of a forbidden path).

Integration tests (`//go:build integration`) run the real thing on the development machine with a temporary home from `testkit` and one root under it: a sandboxed read of `~/.ssh` (a fixture folder with a fixture key) fails; a sandboxed write to `~/.nerdgenie` fails; a sandboxed write inside the root succeeds; a sandboxed network call to a `testkit` loopback server succeeds; a command that sleeps past its timeout is killed with its whole process group (start a child that starts a grandchild, then assert both are gone); a command's output past the cap is dropped with the note; the helper refuses to run outside the fence. A separate integration test renames `bwrap` off the PATH (by a fake empty PATH) and asserts `Available()` names it.
