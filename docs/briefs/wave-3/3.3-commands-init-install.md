## What to build

**The registry.** `Register(contract.Command)` refusing a duplicate name; `Lookup(name)`; `Help()` producing the `/help` text, one line per command in registration order; and a `Run(ctx, line, where)` that splits the slash command from its arguments, refuses a terminal-only command on any other channel with the one-line answer, and calls the command. `serve.go` fills the registry with every package's exported commands.

**The core commands**, exported as `contract.Command` values, each needing nothing from a wave-3 neighbor except through a `Deps` struct of functions the orchestrator fills: `/help`; `/status` (the model alias, the token cost so far, the jobs, the pending previews, and the health of each channel, from functions in `Deps`); `/model` (show or set the alias for the session, checked against the configuration's aliases); `/new` and `/sessions` (a session is one conversation; start a fresh one, or list and switch, through `Deps`); `/approve <id>` and `/deny <id>` (answer a pending preview or question through `Deps`); `/pause` and `/resume` (pause and resume all scheduled work through `contract.Job`: pause every running scheduled job, and resume the ones this command paused); `/undo` (restore the last turn's file changes: read the file-change events of the last turn from `contract.Store`, newest first, and put back each file's prior contents, or remove a file that did not exist, then say what was restored).

**`coeus init`.** Creates the home folder layout with the modes from `contract` (an existing home changes nothing unless `--reset-config` is given) and the work folder `~/coeus` that `contract.DefaultSandboxRoots` names, which is the only place a sandboxed command or a file tool may reach until the user adds more; asks which folders Coeus may work in (default the work folder; each answer checked through `config`'s root rules, so the whole home directory is refused with the reason); writes the three persona files with one explaining line each; asks which model to use with a short numbered menu built from what it detects, in this order: the local llama-server daemon at the default address when its health answers, an LM Studio server at `http://127.0.0.1:1234/v1` when it answers, the Claude subscription when the `claude` program is on the PATH, the ChatGPT subscription when `codex` is on the PATH, Anthropic with an API key, OpenAI with an API key; for a key it asks through the vault's masked prompt and stores it in the vault as `secret://anthropic` or `secret://openai`; writes `config.toml` from a template this package owns (the model alias, the default model, the fallback chain of the other detected models in the same order, and a comment on every line); runs `config`'s doctor and prints it; then prints the five commands a new user needs: `coeus` to talk in the terminal, `coeus signal link` when signal-cli is installed, `/help`, `/tasks`, and `coeus doctor`. It asks at most six questions, takes under two minutes, and accepts every answer as a flag (`--model local`, `--work-folder ~/Code`, `--api-key-from-env ANTHROPIC_API_KEY`, `--signal off`, `--yes`) so a container can run it without a keyboard; with `--yes` and no other flags it picks the first detected model.

**`coeus doctor`.** Runs `config`'s doctor and prints the report, exit code zero when everything is right and one otherwise. The doctor of brief 1.3 is being extended with a probe that bwrap can make a user namespace on this machine; when it cannot, the report names the fix (an AppArmor profile for bwrap on Ubuntu 24.04, which brief 6.2's installer writes).

**`coeus install`.** Writes the systemd user unit once to `~/.config/systemd/user/coeus.service`, pointing at the `current` symlink under the releases folder (which `install` creates to point at the running binary when there is no release yet), with `Type=notify`, `WatchdogSec=60`, `Restart=on-failure`, `RestartSec=5`, `SuccessExitStatus=75` with `RestartForceExitStatus=75` for the restart-me code, and `RestartPreventExitStatus=78` for bad configuration; enables and starts it with `systemctl --user`; prints what it did. `coeus uninstall` stops and disables the service, removes the unit, and leaves the home folder unless `--purge` is given, which asks for a typed confirmation.

**Bounds.** The menu waits with a deadline; the typed confirmation is compared exactly; `/undo` restores at most the last turn's files and refuses when there is no turn.

## Tests, in the order you write them

1. The registry: register, duplicate refused, lookup, help text golden, a terminal-only command refused on the fake Signal-shaped channel.
2. Every core command through the fake channel with a `Deps` of fakes, one test each, with the reply text golden.
3. `/undo` restores a file from the fake log, removes one that did not exist, and refuses when there is no turn.
4. `init` on an empty temporary home, driven by scripted answers on a pipe, produces a config that loads and a passing doctor, the persona files, and the right modes.
5. `init` with every answer as a flag runs with no terminal at all; `--yes` alone picks the first detected model against a `testkit` server standing in for the daemon.
6. `init` on an existing home changes nothing without `--reset-config`, byte for byte.
7. The unit file is a golden file; `install` writes it under a temporary `XDG_CONFIG_HOME` and calls a fake `systemctl` on the PATH that records its arguments; `uninstall` reverses it and leaves the home unless purged.
8. A fuzz test on the command-line splitter: any line, no panic.
