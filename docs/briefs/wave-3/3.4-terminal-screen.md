# Brief 3.4: the terminal screen

Before you write anything, read these five files in this order: `CLAUDE.md` for the rules and the commands, `COEUS.md` for the plain-words explanation of the state design and the check table that ties each claim to a brief and a test, `ARCHITECTURE.md` for how the code is put together and what earlier waves built, `REPO_MAP.md` for where everything lives, and `docs/NERDGENIE_PLAN.md` for the design you are implementing, especially the section this brief names. Then read this brief and the reference files it points at. You own exactly one package. Write the tests first.

## The package

`internal/tui`, plus `cmd/nerdgenie/tui.go` defining the `tui` subcommand value, which the orchestrator maps to the bare `nerdgenie` command. **The design of the screen is `docs/TUI_DESIGN.md`; read it before anything else and build exactly that.** Design section 12, "Terminal", and the second checklist item of the human trial in `docs/WORK_PLAN.md` Part 1 (first frame at once, streaming visible, an approval answered inline, a masked prompt that never echoes, no flicker on resize). The plan text is `docs/WORK_PLAN.md`, Part 3, Brief 3.4. You build on `contract` (the socket envelope, the home's socket path, the command type) and `testkit` (the fake clock, the golden helper). You do not import `channel`, `loop`, `command`, or `signal`; the screen is a thin client that talks to the running program over the socket and holds no state of its own.

## What to build

- **Bubble Tea.** `github.com/charmbracelet/bubbletea`, `bubbles`, and `lipgloss`, which are pre-approved; add them with `go mod tidy`. One model, one update function, one view function, split into files by concern (the header, the transcript, the cards, the input, the status strip, the socket client) each under five hundred lines.
- **The socket client.** Connects to the home's socket path, sends `attach`, reads envelopes line by line into Bubble Tea messages, reconnects with backoff when the connection drops (the status strip says so), and sends `message`, `command`, `approve`, `deny`, `secret`, and `detach`. The client is behind a small interface so the tests use a fake socket from `testkit` or one this package's tests provide.
- **The frame** exactly as `docs/TUI_DESIGN.md` draws it: the header, the rule, the transcript with its four block kinds, the rule, the input box, the status strip; the colors, the key bindings, the command palette, the masked prompt, the pictures, and the motion rules, each as the document says. The first frame is drawn before the socket connects. The spinner appears after five hundred milliseconds and stays at least three seconds, on `contract.Clock`. Deltas are coalesced every thirty milliseconds. Resize re-wraps without clearing the screen.
- **The subcommand.** `nerdgenie tui` starts the screen, and, when no program is listening on the socket, says so in the status strip and keeps trying, so the person never sees a crash.
- **Bounds.** The transcript keeps a capped number of blocks and drops the oldest; the input is capped in length; a socket line past the cap is dropped with an error card.

## Tests, in the order you write them

Screen code is tested by rendering the view to a string at a fixed size and comparing golden files, with the fake clock driving time and a fake socket driving events.

1. The golden first frame at eighty by twenty-four before any socket message, exactly as `docs/TUI_DESIGN.md` describes it.
2. Spinner timing on the fake clock: absent at four hundred milliseconds, present at five hundred, still present at three seconds when the reply arrived at one second, gone after.
3. An approval round-trip against the fake socket: a preview envelope draws the card; `a`, `A`, and `r` each send the right envelope and the transcript records the answer in one dim line.
4. The masked prompt never echoes: the frame contains only bullets, and the sent envelope carries the secret.
5. Streaming: deltas coalesce into one reply block whose text equals their concatenation.
6. Resize from eighty to sixty and back produces the same transcript text with different wrapping and no leftover characters.
7. `NO_COLOR` renders the same structure.
8. The command palette lists and filters registered commands.
9. A disconnect shows the state and the client reconnects on the fake clock's backoff.

Coverage seventy percent, as the plan allows for screen code.
