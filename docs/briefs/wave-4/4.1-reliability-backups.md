## What to build

- **The crash-loop breaker.** Counts unclean starts within a window from a small file under the run folder; past the limit it keeps the program serving but refuses to start a task, sends one message to the user's channel, and clears itself after a quiet period.
- **The turn lease.** One lease per session, taken before a turn and released after; a second turn on the same session waits five seconds and is rejected with a message when the lease is still held.
- **The delivery ledger.** Every reply is written to the log as a reply event before it is sent and marked delivered after; on start, undelivered replies are sent again with the duplicate marker text prefixed, at most three attempts over twenty-four hours, and then given up with a log line.
- **The lifecycle sentinel.** A file written on start and removed on clean exit; when it is found on start, the exit was unclean, and a quick integrity check runs on the database (`PRAGMA quick_check`) before anything else; a corrupt database is renamed aside with the time in its name and the latest backup restored, with a message to the user.
- **The drain marker.** A file with the boot id and a thirty-minute expiry that tells the loop to finish the running task and take no new one, for the updater of wave 6.
- **The deadline.** One primitive for the fifteen-minute turn and the seven-minute tool limits, from `contract`'s caps, on `contract.Clock`, that the loop already respects; this package owns the type so both limits are the same code.
- **The watchdog feed.** Through `github.com/coreos/go-systemd/v22/daemon` (pre-approved), send `READY=1` when `/readyz` first answers and `WATCHDOG=1` at half the interval systemd announces, and stop feeding when the breaker trips, so systemd restarts the program.
- **Backups.** `coeus backup` writes one age-encrypted tar of the database (a consistent copy through `VACUUM INTO`), the vault, and the browser profile folder to the configured backup path with the date in its name, keeping the last seven; `coeus restore <archive>` puts them back into an empty home and refuses a home that is not empty unless `--force`. The nightly run is a systemd user timer, `coeus-backup.timer` and `coeus-backup.service`, which `coeus install` writes beside the main unit; you add them to `install.go` and to its golden test.

## Tests, in the order you write them

1. Each mechanism on the fake clock: the breaker trips at the limit and clears after the quiet period; the lease waits five seconds then rejects; the ledger resends with the marker and gives up after three attempts over twenty-four hours; the sentinel detects an unclean exit; the drain marker expires at thirty minutes; the deadline fires at both limits.
2. A kill mid-turn: a helper process writes a reply event, is killed with `SIGKILL` before marking it delivered, and the restart resends it with the duplicate marker (integration).
3. A corrupt database (bytes overwritten in the middle) is renamed aside and the latest backup restored (integration).
4. `backup` then `restore` into an empty home reproduces the database, the vault, and the profile byte for byte; seven archives are kept and the eighth removes the oldest (integration).
5. The watchdog feed sends `READY=1` and then `WATCHDOG=1` on the fake clock to a fake notify socket the test opens.
6. The timer and service units are golden files, and `install`'s golden test covers them.
7. A fuzz test on the archive reader: any bytes, no panic, always an error that names the archive.
