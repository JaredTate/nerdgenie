## What to build

- **The files.** `MEMORY.md` (facts about the world) and `USER.md` (facts about the user) under the persona folder, each capped at its `contract` size; a save that would pass the cap moves the oldest facts of that file into a dated note in the memory folder and says so in the log. Every fact is one line with its source and date. The memory folder holds markdown notes for anything larger.
- **The index.** A full-text index in the one SQLite file, over every fact, every note, and every past message from the event log, kept current by an indexer that runs on save and on each new message event. Use the driver's full-text search tables if the pure-Go driver has them; otherwise a plain table with a tokenized column and a simple ranking, and say which in `doc.go`.
- **Search, get, save, hint.** Search returns facts newest first up to the limit; get returns one by id; save writes a batch atomically (the files and the index together, or neither); hint returns at most three lines for the current step's text, chosen by search and cut to one line each, and nothing when nothing matches. Supersede, never delete: a fact that replaces another names it, and the old one stays searchable and is marked superseded in results.
- **Zero-token capture from the event log.** From the events of a finished task, with no model call: the files changed, the commands run, the sites visited, the jobs created, and any user message that begins with "no", "actually", "always", "never", or "don't", kept word for word as a correction with the task as its source. A capture runs when the loop tells it a task ended (a function `serve.go` wires), and it is idempotent.
- **`/memory`.** A `contract.Command`: `/memory` shows the two files' sizes and the last ten facts; `/memory search <words>`; `/memory forget <id>` supersedes a fact with a note that the user withdrew it.
- **Bounds.** The index rebuild is capped per run; search results are capped; the hint is three lines of at most one hundred and twenty characters each.

## Tests, in the order you write them

1. The caps: a save past the cap moves the oldest facts into a dated note and the file stays under the cap.
2. Supersede keeps the old fact searchable and marked.
3. An empty hint when nothing matches; three lines when three match; one line each.
4. Each capture rule, one test each, on a fake log holding a finished task's events; a second capture of the same task changes nothing.
5. A correction is retrievable the same turn it was captured.
6. The twenty-question memory test: a recorded session under `testdata/` with twenty facts and twenty questions, each answered by search with the right fact in the top three; this suite runs at every gate from now on.
7. The contract check from `testkit` passes; the integration test runs on the real database in a temporary home.
8. A fuzz test on the fact-line parser: any bytes, no panic.
