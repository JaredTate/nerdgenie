# Brief 5.4: how to extend Coeus, proven by a worker who only reads the documents

Before you write anything, read these five files in this order: `CLAUDE.md` for the rules and the commands, `COEUS.md` for the plain-words explanation of the state design and the check table that ties each claim to a brief and a test, `ARCHITECTURE.md` for how the code is put together and what earlier waves built, `REPO_MAP.md` for where everything lives, and `docs/COEUS_PLAN.md` for the design you are implementing, especially the section this brief names. Then read this brief and the reference files it points at. You own exactly one package. Write the tests first.

## The package

`docs/EXTENDING.md` and `examples/tools/wordcount/`, plus one functional test in `test/functional/`. Design section 6 (the four extension points and the promise that each is one new file against a contract). The plan text is `docs/WORK_PLAN.md`, Part 3, Brief 5.4. You build on `contract`, `testkit`, and `internal/tool` (the registry that loads a user tool). You are the proof that the documents are enough: do not read any other package's code before writing the document, and say in your report whether you had to.

## What to build

- **`docs/EXTENDING.md`**, four sections of about ten lines each, one per extension point (a chat service, a tool, a skill, a model provider), each saying: the contract to implement, in `internal/contract`; the fake to test against, in `internal/testkit`; the contract check to run; and where the file goes and how `serve.go` picks it up. Plain English, terms explained on first use, and one worked example per section pointing at a file that exists.
- **`examples/tools/wordcount/wordcount`**, a shell script that answers `--describe` with the JSON `contract` defines (name `wordcount`, a description under forty words, one field `text`, class `R`) and, given a JSON object on standard input, prints the number of words in `text`. A `README.md` beside it of ten lines.
- **The functional test**, in `test/functional/`, that copies the script into a temporary home's tools folder, starts the registry, and has the fake model call `wordcount` through the loop's contract as the sample functional test does, asserting the count comes back.

## Tests, in the order you write them

1. The example tool registers through the real registry and runs end to end.
2. The document's four contract checks are the ones that exist in `testkit` (a test lists them by name and compares).
3. A bad `--describe` from a copy of the script with the description lengthened is refused with the message the document says.

## Definition of done

Everything in "Definition of done, for every package" in `docs/WORK_PLAN.md` Part 1 that applies to a document and a script. `make check` clean on your branch. `REPO_MAP.md` regenerated. `ARCHITECTURE.md` gets one line pointing at `docs/EXTENDING.md`. You do not touch any other package.
