## What to build

- **`make release`.** Builds `bin/nerdgenie` for `linux/amd64` and `linux/arm64` with the version from `git describe` in `-ldflags`; bundles the two workers' `dist/` folders with a pinned Node runtime for each architecture (downloaded once into a cache, checksum-verified, so a user does not need Node installed); writes `dist/nerdgenie-<version>-<arch>.tar.gz` for each architecture, a `SHA256SUMS` file, and a `manifest.json` with the version, the date, the architectures, and the checksums; and, when run in the release workflow with a tag, publishes them as a GitHub release. The updater of brief 6.3 reads that manifest.
- **`scripts/install.sh`**, under two hundred lines, POSIX shell, run with `curl ... | sh` or from a file: checks the distribution (Ubuntu and Debian first, with a plain message for others); installs `bubblewrap`, `ripgrep`, and `signal-cli` with the system package manager, or from a pinned download with a verified checksum when the package manager lacks one; on Ubuntu 24.04 and later, where AppArmor blocks unprivileged user namespaces, writes the profile `/etc/apparmor.d/bwrap` (`abi <abi/4.0>, include <tunables/global>, profile bwrap /usr/bin/bwrap flags=(unconfined) { userns, include if exists <local/bwrap> }`) and reloads it with `apparmor_parser -r`, then proves it with `bwrap --unshare-user --ro-bind / / /bin/true`; creates the work folder `~/nerdgenie`; tells the user plainly that Chrome must be installed by them and how; downloads the release for the architecture, verifies the checksum against `SHA256SUMS`, unpacks it under `~/.nerdgenie/releases/<version>/`, links `current`, puts a `nerdgenie` launcher on the PATH that runs through `current`; and runs `nerdgenie init`, passing through any `--` flags. A `--from <path>` flag installs a local `make release` archive instead of downloading, for tests. Every step prints one line saying what it did, and a failure says what to do.
- **The CI test.** `.github/workflows/install.yml` runs the installer with `--from` on a clean Ubuntu container and a clean Debian container, with every `init` answer as a flag, and ends with a passing `nerdgenie doctor`. The same test runs locally through Docker or Podman when one is present, and says so when neither is.
