## What to build

- **Replay.** Given a task id, read its events from the log, and run the loop again against the current code with a model and a tool registry that answer from the recorded events: the model returns the recorded replies in order, and each tool returns its recorded result. The replay passes when the record's final state matches the recorded one and the done-check gives the same answer; it fails naming the first step that differed. `nerdgenie replay <task>` runs it and prints the result; `nerdgenie replay <task> --as-test` writes a Go test file under `test/replays/` that runs the same replay under `go test`.
- **The nightly self-check.** A job registered through `contract.Job` at start (once, idempotently) with a daily schedule, whose task runs the twenty-question memory test from `internal/memory` and every recorded skill's dry run, and reports one line on the user's channel: how many passed, how many failed, and the names of the failures.

## Tests, in the order you write them

1. Replay a recorded failing task from `testdata/` (a fixture log), apply a fixture fix (a flag the test flips), replay again and pass.
2. `--as-test` writes a test that compiles and passes.
3. The nightly job fires on the fake clock through the fake job store and reports through the fake channel.
4. A fuzz test on the recorded-event reader: any bytes, no panic.
