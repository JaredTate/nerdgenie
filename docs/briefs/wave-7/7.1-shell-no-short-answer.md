# Brief 7.1: the shell tool answers a repeated command in full

Read `docs/briefs/wave-7/COMMON.md` first. You own `internal/tool/shell`.

**What is wrong.** `internal/tool/shell/unchanged.go` remembers the output hash of the last twenty runs and, when the same command writes the same thing again and exits zero, answers "same as the last run of this command, unchanged: exit 0, N lines; tail pN to read it again" instead of the output. Two things break on that. First, the harness's own checks run through this tool: `internal/loop/syntax.go` runs `node --check '<file>'` after every write or edit, and the second check of any file gets the short answer, whose first line says "exit 0" and not "exit code 0", so the checker reports "does not parse: same as the last run…" for a file that parses. On task 8 of the night of 6 September, 34 of the model's 46 writes and edits were told they did not parse, it rewrote one correct file byte for byte 21 times, and because a file that "does not parse" is never tested, no write in the whole task carried a tests-after-this-change line. Second, the model wanted the 23 lines it had asked for; it never used the pointer, and asked 17 more times. The short answer's one real job, stopping a model that reruns a command, belongs to the same-call guard, which brief 7.2 fixes.

**What to build.** Remove the short answer and its memory. A command that writes the same thing as last time is answered in full, like any other. Keep `serve` and `check` exactly as they are. Delete `RunsRemembered`, `pastRuns`, `remember`, `forget`, `countLines` and `answerRun`'s short path if nothing else uses them; keep the file's other jobs. If `unchanged.go` ends up holding only serve and check, rename it to what it holds and run `make repo-map`.

**Tests first.** Replace `TestTheSameCommandWithTheSameOutputIsAnsweredShort` with `TestTheSameCommandWithTheSameOutputIsAnsweredInFull`: the same command run twice answers the second time with its whole output and "finished with exit code 0" on the first line. Add `TestACommandThatWritesNothingIsAnsweredInFullBothTimes`: a command with empty output, run twice, answers "finished with exit code 0" both times, which is what the syntax checker reads. Watch both fail before you change the code.

**Docs.** In `ARCHITECTURE.md`, find the paragraph on the shell tool that describes the unchanged-run answer (search for "same as the last run") and rewrite it to say the answer was removed on 7 September 2026 and why, in two sentences. In `NERDGENIE.md`'s check table, the row "Starts a server and answers the moment it listens, checks a port with no shell, and answers an unchanged command short" loses its last clause and the test name `TestTheSameCommandWithTheSameOutputIsAnsweredShort`. Three lines in `docs/PROGRESS.md` under the heading "The unchanged-run answer removed, 7 September".
