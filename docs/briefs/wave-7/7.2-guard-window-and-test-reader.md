# Brief 7.2: the guard counts repeats across its window, and the test reader has a last resort

Read `docs/briefs/wave-7/COMMON.md` first. You own `internal/loop`, but only these files: `guard.go`, `guard_test.go`, `teststate.go`, a new `teststate_generic.go` and its test. Brief 7.3 owns the rest of the package this wave; do not touch `calls.go`, `progress.go`, `endings.go`, `stopdone.go`, `freshwindow.go` or `rewindIfDue` in `guard.go`.

## Part one: the guard

**What is wrong.** `sameResultStreak` in `guard.go` counts the newest calls in a row that asked the same thing and got the same answer, and "a different call in between ends the run". On task 8 the model alternated: the same refused edit, then a write, then the same refused edit; the same `sed` read, then `npm test`, then the same read. Nineteen identical refused edits over 27 minutes and seventeen identical reads never tripped the first rule. The guard fired only at the end, on a strictly consecutive run.

**What to build.** The first rule counts the same call with the same answer anywhere in the window (`Caps.IdenticalCallWindow`, twenty), not only in a row: how many calls in the window carry this mark and whose result fingerprint equals the newest result for this mark. `IdenticalCallsAllowed` keeps its value and meaning: the third such call is refused and not run, the fourth rewinds. `sameCallRun` and `SameCallHardCap`, the second rule on repeats whatever they answered, stay consecutive, because seven test runs after seven edits with improving results is honest work. A call the detector itself refused has no result and counts for nothing, as now. Polls stay exempt as they are now; find how and keep it. Update the comments on the constants and the two functions so they say what is counted and why.

**Tests first, in `guard_test.go`.** `TestTheSameCallWithTheSameAnswerIsCaughtAcrossOtherCalls`: A, B, A, B, A where every A answers the same thing: the third A is refused and not run. `TestAFourthSameAnswerAcrossOtherCallsRewinds`: one more A sets the rewind. `TestAnEditAndTestCycleWithImprovingResultsIsNotARepeat`: the same test command seven times in the window, each answering something new, runs every time. The existing guard tests, the forty-step fixture (which reads the same page twice in a row on purpose at rounds twenty-nine and thirty) and the poll tests must still pass.

## Part two: the test reader

**What is wrong.** `testStateIn` in `teststate.go` knows node:test, Jest, Vitest, Mocha, Bun, Deno, pytest, unittest, Go and the C-family runners. On task 8 the model wrote its own runner (`test.js`, "zero-dependency Node test runner"), and its output was read as no test run at all for the whole task: no test line in the situation, no rerun after a change, no stuck-test line, no test-based progress. Its output, word for word from result r133:

```
finished with exit code 1
  ✓
  ✓
tests/lineClearAnim.test.js ...   ✓
  ✓

──────────────────────────────────────
FAIL tests/engine.test.js :: game ends when the stack reaches the top
     Error: game over detected
         at fail (~/Desktop/Tater Tots Tetrisv1/test.js:25:30)
         at Object.ok (~/Desktop/Tater Tots Tetrisv1/test.js:27:32)

143 tests, 142 passed, 1 failed
```

**What to build.** A last resort in a new file `teststate_generic.go`, tried only when no known runner matched: a summary line of the shape "N passed, M failed", or "N tests, N passed, M failed", or "N passed" alone with "M failed" on the same line, in either order, gives the counts; a line beginning "FAIL " with " :: " in it names the failing test as the part after " :: ". A line that merely contains the words, a file listing with "passed" in a name, a sentence such as "all tests passed", or a numbered list, must not read as a run. Keep `teststate.go` under five hundred lines; it is at 354.

**Tests first, in `teststate_generic_test.go`.** `TestAHomeMadeRunnersSummaryLineIsReadAsATestRun` on the output above: 143 tests, 1 failing, named "game ends when the stack reaches the top". `TestTheGenericReaderIsTriedOnlyWhenNoRunnerMatched`: a Jest sample still reads as Jest. `TestWordsThatLookLikeASummaryAreNotARun`: the negatives above. Add one line to `TestOutputWithTheRunnersWordsIsNotATestRun` if it fits better there.
