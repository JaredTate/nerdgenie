# Brief 7.3: the rethink, which turns a stall into a new angle

Read `docs/briefs/wave-7/COMMON.md` first, then `ARCHITECTURE.md`'s turn-loop section in full, and read `internal/loop/guard.go`, `calls.go`, `progress.go`, `freshwindow.go`, `review.go`, `stopdone.go` and `endings.go`. You own `internal/loop`. Brief 7.2 owns `guard.go`'s two counting functions and the `teststate*` files this wave; you may change `rewindIfDue` in `guard.go` and nothing else in that file, and nothing in `teststate*`. Put your new code in new files: `rethink.go` and `rethink_test.go`, and `closedcalls.go` if it keeps `rethink.go` under five hundred lines.

**What is wrong.** When the model goes round in circles the loop cuts the stalled rounds, writes "stalled: asked for X over and over" into the record, and appends `TheRewindLine`, which tells the model to do something different. On task 8 of the night of 6 September that happened, and the model's first line then said "I have been looping, time to stop circling" for fifty rounds while it made the same call. Words do not change what a 3-bit model does; what is in front of it does. Two more things from the same log. At 03:17 the same model hit a different bug and solved it in four rounds by writing small scripts that traced the code as it ran; for the bug it never solved it never wrote one probe, it re-read the same twenty-five lines. And it wrote failure F3 with the wrong cause at 03:25, and every round after built on F3 because the record is the truth and nothing made it check.

**What to build.** A stall becomes a rethink. Where `rewindIfDue` now cuts and appends the rewind line, on both paths that set `rewindDue` (the guard's run of the same call in `calls.go`, and the meter's twenty rounds without progress in `progress.go`), it does this instead:

1. **One call with the tools off, in a small fresh window**, made the way `askTheFourQuestions` in `review.go` makes its call, through `Context.Build` with `ToolsOff: true`. The messages are two: a background and the question. The background holds the record as it stands, the full text of the newest result on the record (through the keeper, capped at `MaxRethinkResultBytes`, 16384, the same cap as one read, so the model has once and in full the thing it kept asking for), and the situation's test line when there is one. The question, `TheRethinkQuestion`, asks for five labelled lines: `Learning:` what you were trying to learn; `Showed:` what the last rounds actually showed; `Symptom:` the symptom in one line; `Causes:` two different causes that could explain it, neither one already written as a failure's cause on the record; `Next:` the one cheapest call that tells those two causes apart, written as something that can be run or read. The background says in one sentence that every cause already on the record was tried and did not hold.
2. **The answer goes into the record through the record's own rules**, `keeper.Apply` with a `Failure{Text: "stalled: " + Showed, Cause: Symptom}` and a `Decision{Text: "Rethink: next " + Next, Reason: "two causes: " + Causes}`. Keep the `stalled:` prefix, because `scripts/runreport` counts rewinds by it. The record cuts a lesson to 120 runes itself; do not cut it twice. A missing label takes the whole answer as `Next`. `ErrFailureAlreadyWritten` is not an error here.
3. **A fresh window**, built the way `reopenTheWindowIfFull` in `freshwindow.go` builds one: the messages cleared, the orientation with the newest results in full, then one user message holding `TheRethinkLine`, the model's whole rethink answer, and the instruction "Do the Next line now." `keepThrough` and the detector's window are reset as they are now.
4. **The call the model was repeating is closed** for `ClosedForRounds`, ten, rounds: its fingerprint goes into a map on the run with the round it reopens at, and `oneCall` in `calls.go` refuses it before the detector with "You already have that; it is on the record as rN. Do the Next line of your rethink instead." Close the mark of the call that set the guard off, and on the meter's path the mark of the newest call.
5. **The stop after the last rethink lists what was tried.** The bounds stay as they are: `RewindsAllowed` on the guard's path and `StallsBeforeStop` on the meter's. When the stop comes, its report gains one line, "Tried by rethink: " followed by every decision on the record whose text begins "Rethink:", so the person reads the ledger. Put the one function that builds that line in `rethink.go` and call it from where the stop's report is written.
6. **A rethink that cannot be made** (the model errors, or the answer is empty) falls back to the plain cut and `TheRewindLine` as today. Nothing here ever fails the task.

Nothing else changes: not the instruction text, not the constants of the guard or the meter, not the providers. A rethink costs one model call and is bounded by the counts that already exist.

**Tests first, in `rethink_test.go`, against the scripted fake model in `internal/testkit`** the way `guard_test.go` and `progress_test.go` drive the loop. `TestARunOfTheSameCallRunsOneRethinkWithTheToolsOff`: the fake model repeats one call until the guard rewinds; the loop then makes one request with `ToolsOff` whose last message is `TheRethinkQuestion` and whose background holds the newest result's text; the record gains a failure beginning "stalled:" and a decision beginning "Rethink: next"; the messages after are a fresh window whose last message ends with "Do the Next line now." `TestTwentyRoundsWithoutProgressRunOneRethinkToo`, the same through the meter's path. `TestTheCallTheModelRepeatedIsClosedForTenRounds`: the same call in the next round is refused with the closed line and not run, and runs again after ten rounds. `TestARethinkTheModelCannotAnswerFallsBackToThePlainCut`. `TestTheStopAfterTheLastRethinkListsWhatWasTried`: the stop's report carries "Tried by rethink:" and each decision. `TestTheRethinkBackgroundIsCappedAtOneRead`: a newest result of a hundred kilobytes is cut to `MaxRethinkResultBytes`. Existing tests that assert the old cut, in `guard_test.go`, `progress_test.go` and `window_test.go`, are updated to the new shape only where the shape changed; the record's own tests are untouched.
