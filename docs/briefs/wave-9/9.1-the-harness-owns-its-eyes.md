# Brief 9.1: the harness owns its eyes

Read `docs/briefs/wave-9/COMMON.md` first. You own `worker/browser` and its `PROTOCOL.md`, `internal/contract/browser.go`, the fake browser worker and its protocol server in `internal/testkit`, `internal/tool/browsershot`, and `internal/tool/browserread`. Nothing else this wave: briefs 9.2 and 9.3 own the job, the record and the loop, and they read the two sentences your tool writes, so keep them exactly as written here.

**What is wrong.** A screenshot of a still scene is byte-identical to the last one, and the tool says "the picture is the same as the last one at this size; nothing to look at again". The model cannot tell a still scene from a broken camera, so it spends its rounds proving the camera is broken. The harness can tell: the page either drew frames since the last picture or it did not.

**What to build.**

1. **The worker counts the page's frames.** Before every screenshot the worker brings the page's window to the front (`page.bringToFront`, which `tabs.ts` already does on a tab switch). Then it asks the page how many animation frames it draws in a quarter of a second, with `requestAnimationFrame` in a page call under the same deadline the ask uses, so a page whose script never yields answers zero rather than hanging. The answer rides on the screenshot result as `framesDrawn`, a whole number. `PROTOCOL.md`'s `screenshot` section says so. Reference: the settle wait in `settle.ts` for the shape of a bounded wait on the page.
2. **The contract carries it.** `contract.Screenshot` gains `FramesDrawn int` with the JSON name `framesDrawn` and a doc comment. The fake worker's screenshot returns the number a test sets, and the fake protocol server passes it through, so the contract check holds the real worker and the fake to the same field.
3. **The tool tells the model what the frames mean.** In `internal/tool/browsershot`, a picture that is the same as the last one is answered with one of exactly these two sentences, the path of the last picture in brackets as now:
   - frames above zero: `the picture is the same as the last one: the page drew N frames in a quarter of a second, so it is alive and nothing on it moved; change the view, move the camera or the aircraft, or act on the page to see something new`
   - frames zero: `the picture is the same as the last one: the page drew no frames in a quarter of a second, so its loop has stopped or the tab is hidden; open the page again or read its console`
   A new picture's text gains one line after the saved-at line: `the page drew N frames in a quarter of a second`. Brief 9.3 reads that line word for word to prove a "photographed" done line, so its shape is fixed.
4. **A page question with no question is refused.** In `internal/tool/browserread`, a call whose intent holds any of the words evaluate, diagnose, run, execute, script, JS, JavaScript, state or read back, and carries no `ask`, is refused with one sentence and one example: `this call's intent says it evaluates something on the page, but it carries no ask; write the expression in the ask field, such as ask: "JSON.stringify(window.sim.state)"`. Five rounds of the sky task were the model saying "I need to pass an ask parameter" and not passing it.

**Tests first.** In `worker/browser/test/`, two fixture pages: `still-canvas.html`, whose canvas draws once and stops, and `live-canvas.html`, whose canvas redraws every frame. `frames.test.ts`: `a screenshot of a page that keeps drawing reports the frames it drew`, `a screenshot of a page that drew once reports no frames`, `a screenshot brings the window to the front first`. In `internal/testkit`: the fake carries the number and the protocol server passes it. In `internal/tool/browsershot`: `TestASamePictureOfAPageThatDrawsSaysNothingMoved`, `TestASamePictureOfAPageThatDrawsNoFramesSaysItsLoopStopped`, `TestANewPictureSaysHowManyFramesThePageDrew`. In `internal/tool/browserread`: `TestAnIntentThatEvaluatesWithNoAskIsRefusedWithAnExample`, `TestAnIntentThatOnlyReadsThePageNeedsNoAsk`. Watch each fail first. Coverage above ninety percent in every Go package you touch, above seventy in the worker.
