## 2. Per-harness narrative

### OpenClaw

The design choice is a **two-layer loop**. The inner layer (`packages/agent-core/src/agent-loop.ts`) knows nothing about providers, retries, or channels. It has an outer `while(true)` for follow-up messages and an inner `while` for tool calls (`:347-351`). Between them sit hooks: `transformContext` and `convertToLlm` before the model call, `beforeToolBatch` before tools, `prepareNextTurn` after (which can swap the model mid-run, `:476-492`), and `shouldStopAfterTurn` to end early (`:497-507`). The outer layer (`src/agents/embedded-agent-runner/run-loop.ts`) is the "keep it alive" loop: it retries whole attempts, rotates auth profiles, fails over models, and recovers from overflow and timeouts.

Two ideas stand out. First, **steering is checked at tool boundaries**, not only between model calls (`agent-loop.ts:764-771`). A WhatsApp user can type while a tool runs and the loop skips the calls that have not started yet. Second, **turn taint**: a tool result from the network marks the turn, and the taint is stamped on the assistant message (`:1721-1760`). Nobody else here tracks provenance inside the loop.

The trade-off is size. The pure loop is under 7k lines; the wrapper is over 400k. There is no cap on turns, so the only brakes are the 48-hour run timeout and the tool-loop detector. Memory is now three plugins deep (memory-core with Dreaming, active-memory, memory-lancedb), each with its own hook into `before_prompt_build`. Powerful, but a lot to reason about for a personal agent.

### Hermes

Hermes assumes the conversation never ends, so most of its engineering is about **shrinking context well** and **writing down what it learned**. The compressor triggers at 50%, protects the head and a token-budgeted tail, summarizes the middle, and quotes real user messages verbatim inside the summary (`context_compressor.py:1082-1117`). That last rule is the sharpest idea in the four: assistant text is an account of the work and survives summarizing; user text is the source of truth and does not.

The learning loop is real and on by default. Every 10 tool iterations without a memory or skill write, the turn finalizer forks the agent into a daemon thread that can only call `memory` and `skill_manage` (`background_review.py:1-14`; `turn_finalizer.py:794-830`). It replays the warm prompt cache, so the fork is cheap. Writes land in `MEMORY.md`/`USER.md` and `SKILL.md` files; the next session reads them back in the volatile tier of the system prompt (`system_prompt.py:925-960`).

The trade-off is readability and latency. `run_conversation()` is one ~7,250-line function. Model calls are non-streaming by default. Parallel tool safety is a hand-maintained allow-list of 12 tools plus path overlap rules; anything else is a barrier. On the gateway, the default reaction to a second message is **interrupt**, which is aggressive for a chat surface. Verify-on-stop, the feature the last report praised, is now off unless you set it.

### Prime

Prime keeps the same loop skeleton as OpenClaw's ancestor (`pi-agent-core`) but gives the model **one tool**, a persistent Python REPL in a child process (`repl-manager.ts:2-4`). Work accumulates in variables, not in the chat log. Cell output is capped at 65,536 chars, which is the pressure that makes the pattern work. Compaction is lossy for the narrative and lossless for the artifacts.

The session wrapper is where the interesting choices live. `shouldStopAfterTurn` is a serialized checkpoint: it accounts goal tokens, runs the refine step, then decides on threshold compaction (`agent-session.ts:2210-2245`). Refinement writes to `harness_state.json` (prompt notes, memories, skills, sub-agent specs) and the very next prompt build appends it via `formatHarnessStateForPrompt` (`system-prompt.ts:105-107`). Auto-refine is on by default with an LLM review gate deciding whether a proposed edit is worth keeping (`refinement.ts:175`). There is a rollback path (`agent-session.ts:8217-8359`).

The trade-off has not changed: **no permission gate**. Approving "run ipython" is approving arbitrary Python. Retries exist but there is no model failover. The 12k-line `agent-session.ts` is a second giant file to read.

### OpenCode

OpenCode is the smallest loop and the cleanest separation of policy from mechanism. The loop is about 250 lines in `prompt.ts` plus a 730-line stream processor. It leans on the Vercel AI SDK for providers, streaming, and tool execution, and on Effect for cancellation and retries. Permission is a flat rule list, last match wins, default `ask`, and every tool asks (`tools.ts:83-408`). The doom-loop detector is three identical calls in a row, which then becomes a permission question rather than a hard stop.

Two details matter for a personal agent. `AGENTS.md` and friends are **re-read from disk every step**, so editing the file mid-session takes effect immediately and compaction cannot lose it. And tool output truncation spills the full text to a file with a 7-day retention, so the model can go back for more.

The trade-off is that OpenCode does not learn. There is no memory tool, no auto-capture, no review fork. The "session -> future session" channel is a human editing `AGENTS.md` or running `/init`. Tool parallelism is whatever the AI SDK does, with no safety analysis. Model failover is absent.

## 4. The loop for the new agent

A recommended turn lifecycle. Each step names where the idea came from.

1. **Accept and ack.** Persist the user message, return a `runId` at once (OpenClaw `agent` RPC). Serialize per session with a writer claim so a superseded run cannot commit (OpenClaw `activeWriterRunId`).
2. **Decide what a mid-turn message means.** Default `steer`: inject at the next tool boundary, let running tools finish, skip unstarted ones with a synthetic error result (OpenClaw `agent-loop.ts:764-771,77`). Keep `followup` and `interrupt` as explicit options. Do not default to interrupt (Hermes gateway does; it is jarring).
3. **Build the prompt in three tiers.** Stable identity and tool guidance; project context files; volatile memory, skills index, and timestamp (Hermes `system_prompt.py:12-21`). Cap each file and the total (OpenClaw 20k/60k chars). Put a cache breakpoint at the end of the stable tier and at the end of the system prompt (Hermes `prompt_caching.py:3-8`).
4. **Re-read context files from disk every step.** Cheap, and it makes compaction safe for anything file-backed (OpenCode `instruction.ts:110-135`).
5. **Stream the model call** through one provider abstraction. Repair plain-text tool calls before they reach the loop (OpenClaw `tool-call-repair`). Validate arguments; on failure return the error as a tool result, not an exception (Hermes `tool_executor.py:1159-1170`).
6. **Admit the tool batch before launch.** One hook sees all calls at once (OpenClaw `beforeToolBatch`). Run the doom-loop check here: three identical calls in a row becomes a question to the user, not a crash (OpenCode `processor.ts:355-375`).
7. **Split the batch into parallel and sequential segments** in model order. Parallel-safe = read-only tools and file tools with non-overlapping paths; everything else is a barrier (Hermes `tool_dispatch_helpers.py:152-176`). Commit results in source order even when execution overlaps (OpenClaw `launchParallelToolCalls`).
8. **Gate every tool call with the same function.** Rule list, last match wins, default `ask`; "always" appends an allow rule (OpenCode `permission/index.ts:28-36,145-149`). Prime's absence of a gate is the one thing not to copy.
9. **Bound every tool.** Timeout per tool (2 min shell default, OpenCode). Truncate output to a fixed cap, spill the full text to a file, and tell the model where it is (OpenCode `truncate.ts`; Hermes head/tail split).
10. **Taint the turn** when a result came from the network, and stamp the assistant message (OpenClaw `agent-loop.ts:1721-1760`). Use the taint to tighten the gate for the rest of the turn.
11. **Check for steering and stop conditions after each turn.** `shouldStopAfterTurn` is the one serialized checkpoint for budgets, refine, and compaction (Prime `agent-session.ts:2210-2245`).
12. **Compact at a threshold, not at failure.** Trigger around 50% of the window (Hermes). Keep a token-budgeted tail with whole tool rounds (Hermes, Prime 20k). Quote user messages verbatim inside the summary (Hermes `context_compressor.py:1082-1117`). Never split a tool call from its result (OpenClaw). Run a silent memory-flush turn first (OpenClaw).
13. **Retry outside the loop.** Transient errors: up to 3-5 attempts with jittered backoff and `retry-after` (OpenCode `retry.ts`). Never retry context overflow (OpenCode `:89`). Auth expiry and model failover live in an outer attempt loop with a budget (OpenClaw `run-loop.ts`).
14. **Delegate without blocking.** Children return a handle; results come back as steering items in the parent's next turn, capped and labeled "data, not instructions" (OpenClaw `agent-steering-queue.ts:14-22`). Depth 1 by default.
15. **End the turn with a finalizer**, not a return. Persist, emit `agent_end`, then decide whether to fork a review (Hermes `turn_finalizer.py:794-830`).

## 5. Learning for the new agent

### Adopt

**1. Two small memory files with hard character caps.** `MEMORY.md` for facts about the world, `USER.md` for facts about JT. Hermes caps them at 2,200 and 1,375 chars (`memory_tool.py:178-179`). The caps are the feature: they force curation and keep the prompt cost fixed.
Read path: load both at session start, place them in the volatile tier of the system prompt after the skills index (Hermes `system_prompt.py:933-940`). Re-read from disk at every prompt rebuild, including after compaction.

**2. Background review fork, on by default.** After a turn, if N tool iterations passed without a memory or skill write, fork the agent into a thread with only `memory` and `skill_manage` tools, replaying the warm cache (Hermes `background_review.py:1-14`). Give it a hard budget: 16 iterations and an input-token cap (`:204-231`). Writes go straight to the files above.
Read path: same as (1). The fork never touches the live transcript, so the read path is simply "next prompt build".

**3. Harness-state notes with review and rollback.** Prime's `harness_state.json` holds four kinds: prompt notes, memories, skills, sub-agent specs (`refinement.ts:30`). Keep an append-only history and a rollback command (`agent-session.ts:8217-8359`). Let an auto-refine run on a turn interval, but gate it with a cheap review model (`refinement.ts:175`).
Read path: `formatHarnessStateForPrompt` appended at the end of the system prompt on every build (`system-prompt.ts:105-107`). Cap the formatted block so it cannot crowd out the task.

**4. Searchable session history.** FTS5 over past transcripts, exposed as a tool (Hermes `session_search_tool.py:8-25`). This is the cheapest form of episodic memory and needs no embeddings.
Read path: on demand only. Never auto-inject.

**5. Agent-authored skills with an index in the prompt.** `SKILL.md` files, name plus one-line description in the prompt, body loaded on use (Hermes `prompt_builder.py:1781-1846`). A `/learn` command that turns "what we just did" into a skill (Hermes `learn_prompt.py`).
Read path: skills index rebuilt from disk at session start and after compaction; snapshot cached to avoid re-parsing.

**6. Silent memory flush before compaction.** One hidden turn that asks the model to save durable notes before the summary is written (OpenClaw `docs/concepts/compaction.md:56,180`). It closes the gap where compaction would otherwise be the moment knowledge is lost.

### Skip, at least for v1

- **Vector memory** (OpenClaw memory-lancedb, memory-core hybrid index). It needs an embedding provider, a store, and a cooldown policy. FTS5 plus small curated files gets most of the value for a single user.
- **Dreaming-style scheduled consolidation.** Interesting, but it adds a third writer to `MEMORY.md` and a whole phase model. Revisit once the review fork has run for a few weeks and you can see what it fails to capture.
- **Pre-reply recall hooks** (OpenClaw active-memory). Every-turn retrieval adds latency and tokens to every message. Do recall on demand through a tool first.
- **Skill curator with LLM consolidation.** Hermes ships it with consolidation off for a reason (`curator.py:74-76`). A personal agent will not have enough skills to need it.
- **Learning graphs and insights dashboards.** They visualize; they do not change the next prompt.

### The one rule

Every mechanism above must have a read path that is a plain file read at prompt-build time or a tool the model calls on purpose. If a mechanism writes somewhere the prompt builder never reads, it is not learning; it is logging. That is the test the prior report applied to Prime's `/refine`, and it still holds.
